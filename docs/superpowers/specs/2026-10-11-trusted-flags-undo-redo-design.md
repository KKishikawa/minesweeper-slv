# 確定地雷としての旗と、盤面・解析結果のUndo/Redo

## 合意した目的と範囲

Issue #26からの設計変更。利用者との対話で、旗は「確定地雷として解析の前提にする入力」に統一し、常時再検討・矛盾時の自動再検討を削除する方針に合意した。

探索限界に到達すると安全・地雷の提案が消えるため、盤面編集を元に戻して以前の盤面と解析結果を確認できるようにする。利用者が選んだ履歴操作は「元に戻す／やり直す」。履歴一覧や永続保存は含めない。

「提案された地雷をすべて旗にする」ボタンは今回は作らない。現行solverも推論で確定した地雷を未確定探索から外しており、旗への一括反映で探索量が削減される保証がない。性能改善、探索予算の変更も本変更の目的にしない。

## 利用者に見える動作

- 旗policyのradioと自動再検討checkboxを削除する。
- 「入力旗は地雷として扱います。誤った旗でも数字と矛盾しなければ、その旗を前提とした提案が出ます。旗が正しいことを確認してください。」と説明する。
- 盤面操作の近くに「元に戻す」「やり直す」buttonを設ける。復元先がないbuttonはdisabledにする。TabとEnter/Spaceで操作できる。
- セル値の変更、盤面リセット、盤面作成を各1操作として記録する。矢印移動、選択、入力方式・パレット変更は記録しない。同じ観測値への入力も履歴を増やさない。ただしsource/uncertainが変わる手動確認は実際の編集とする。
- 幅・高さ・総地雷数を含めて復元する。盤面作成formの値も復元した盤面に同期する。通常の再描画で未送信のform入力を上書きしない。
- Undoの後に新たな盤面編集をするとRedo側の履歴を破棄する。再解析だけでは破棄しない。
- 履歴は現在を含む直近100盤面をページ内メモリで保持し、古いものから削除する。保持範囲を短く説明し、再読み込みで消えることを案内する。
- 探索限界・矛盾・エラーの盤面に古い別盤面の提案を重ねない。元に戻したときだけ、その復元盤面と一致する保存済み結果を表示する。
- 結果を復元したことを短い説明で知らせる。「再解析する」は引き続き利用できる。

初回はbuttonによる履歴操作に限定する。Ctrl/Cmd+Zなどの独自shortcutは追加せず、formのnative編集操作を維持する。

## スナップショット方式

差分を積み上げず、各履歴entryに以下を保持する。

1. 盤面の幅・高さ・総地雷数と全セルのvalue/source/uncertain。
2. 最後に確定した表示状態：validation、phase、proposal、安全・地雷・推測候補、message、limitReason。
3. そのentryで最後に成功した解析結果（solved/guess-required）。再解析が後から失敗した場合にも、同じ盤面で過去に得た提案を復元できるようにする。

実装では完了状態の記録を共通化し、成功結果を二重cloneせずに共有してよい。履歴とlive stateはimmutableに扱い、配列を後から書き換えて他の履歴を変えない。境界でのcloneまたは不変オブジェクトへの参照で、snapshotの独立性を保証する。

activeRequestId、nextRequestId、実行中Worker、timer、診断履歴、選択セル・focus・palette・入力方式はsnapshotへ含めない。board.revisionは履歴entryの同一性・復元時の実行IDとして使わず、復元時には新しいrevisionを割り当てる。

## 状態遷移と非同期解析

履歴は現在entryと前後のentryを管理する。stateの遷移が履歴操作の正否を決め、appはbutton表示と副作用の実行を担う。履歴のsnapshot型はlive AppStateと分ける。

### 盤面編集

1. 現在entryに、その盤面で受理済みの表示結果を保存する。実行中状態を完了結果として保存しない。
2. Redo側を破棄し、新盤面entryを追加する。保持上限を適用する。
3. 旧Workerをcancelし、単調増加するrevision/requestIdで新盤面をtrusted解析する。
4. 受理した応答は現在entryの結果を更新する。応答自体は編集履歴を増やさない。

### Undo/Redo

1. 戻り先がなければ何もしない。あれば現在entryを保存し、旧Workerをcancelする。
2. 履歴cursorを移動し、盤面を新しいrevisionで復元する。nextRequestIdは巻き戻さない。
3. 保存された成功結果があれば、それを復元しWorkerを起動しない。成功結果がなくても完了した矛盾・limit・error等があれば、その状態を復元する。
4. 解析が未完了で、保存結果がないentryに戻った場合は、validationを行い新requestIdで解析する。invalidならその確認状態を表示する。

復元したphaseをsolvingのまま放置しない。復元時に成功結果を使った場合は「保存された解析結果を表示しています」と示す。以前の成功結果を復元できるのは、寸法・総地雷数・全セル観測が同じentryに限る。

### 再解析

履歴entryは増やさず、現在entryの解析を新requestIdで実行する。以前の成功結果は履歴側に保持するが、解析中や失敗時のlive表示には重ねない。再解析完了は現在entryだけを更新する。

revisionが安全な整数の上限に達する場合は、現行と同様にRangeErrorで不正な遷移を拒否する。履歴復元でもrevisionを再利用しない。

## 固定方式への変更と削除する挙動

- app stateの選択policy、自動再検討、effectivePolicyの切替とsettings-changed経路を除去する。
- solver・validation・constraints・Workerからreconsidered分岐を削除し、旗を固定地雷としてのみ扱う。policy引数の整理はその関連呼び出し・testsまで一貫して行う。
- 矛盾した旗を未確定として再試行しない。矛盾時は旗・数字・総地雷数の確認を促し、手動修正またはUndoへ誘導する。
- 旗を付けたマスへ安全・地雷・推測提案を返す旧経路を削除し、旧再検討用の凡例説明・併記例を更新する。入力旗とsolver提案の表示区別は維持する。
- 失われる機能は、誤旗を未確定として解析することと、旗依存の矛盾時の自動回復。代替は手動で旗を閉じたセルへ直すか、Undoで旗を置く前へ戻すこと。矛盾しない誤旗の検出は引き続き保証しない。

## 診断データ

編集履歴と開発者向け診断履歴は独立する。保存結果の復元は新たなsolver実行をしないため、診断entryを作らない。実行中のUndoは通常のcancelとして記録され、実際に再解析したときだけ新entryを作る。

schemaVersion 1のexport形状は維持し、policy/effectivePolicyは常にtrusted、autoReconsiderは常にfalseを出力する。これらは診断の解析方式を明記するmetadataであり、利用者向け設定や切替処理としては残さない。

replayはtrustedのみ実行する。過去のeffectivePolicy: reconsideredのentryは「再検討方式は削除されたため、元のbuild commitの旧版で再実行する必要がある」と明示して拒否する。trustedへ読み替えて異なる結果を出さない。既存の診断記録・実機証跡は歴史資料として保持する。

## 検証

- 固定旗のsolverを小盤面総当たりoracleで比較する。旗依存の矛盾は停止し、矛盾しない誤旗は前提として扱われることを確認する。
- state testsで編集→完了→編集→limit→Undoにより元盤面と安全・地雷提案が復元され、Workerを起動しないことを確認する。
- Undo/Redoの端、分岐、新編集、100entry上限、snapshot独立性、no-op、リセット・寸法変更の復元を確認する。
- 解析中Undo、未完了entryへの復元、復元後の古い応答、再解析後の失敗と保存成功結果を確認する。
- browser testsでbuttonのdisabled/Tab操作、設定値同期、旗修正・Undoによる矛盾からの復帰、実際の結果表示復元を確認する。limitは制御可能なWorker fixtureで再現し、時間依存の偶然にしない。
- 入力安定性・凡例・出荷smokeの既存testsを新仕様へ更新し、型検査・全tests・production buildを実行する。
- 製品定義・プライバシー／保持説明・診断手順・Issue #26の設計変更記録を更新する。旧W5/W6の実機結果を新仕様の合格へ流用しない。

## 採用理由と制限

最大900セルの盤面を100entry保存する方式は、差分履歴より復元時の整合性を確認しやすい。保持量は履歴上限で制限し、永続化しない。実装時には無用なcloneや履歴の再描画を避ける。

履歴は探索量を減らす機能ではなく、解析できていた状態へ戻して確認・修正を続ける機能である。戻せるのは保持された履歴の範囲内だけで、以前の提案が現在の別盤面にも成立することは示さない。
