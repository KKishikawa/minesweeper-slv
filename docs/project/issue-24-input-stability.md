# Issue #24 入力時の描画・レイアウト調査

対象: https://github.com/KKishikawa/minesweeper-slv/issues/24

## 環境と現時点の結論

2026-10-10、commit `1a01eac` のproduction buildをMac上のPlaywright Chromiumで計測した。確認者の指示により、今回はWindows実機の録画・再検証を完了条件から外し、Chromiumの計測と操作・レイアウト検証で判定する。過去のWindows実機で知覚された「画面全体のちらつき」と同一のGPU paint現象を確定したものではない。

3表示サイズ × 9×9・10地雷 / 30×16・99地雷の全6ケースで、入力のたびに同寸法のCanvas初期化と結果欄の高さ変動を観測した。結果欄の高さ変動 → workspaceのResizeObserver → renderの再実行という追加描画も記録とコードで対応する。矢印移動ではselectとfocusinが重なり、盤面を2回描画する。DOMセルは入力ごとに再作成されていない。

## 修正前の計測

入力列は `0, Delete, F, Delete, 1, Delete, ArrowRight, 0, Delete` を100ms間隔、その後 `F, Delete, 0, Delete, 1, Delete` を待機なしで連続入力。設定変更と初回フォーカスのスクロールは集計対象外。実Workerを使用した。各キーの時刻から次キー直前までのイベントがその入力の計測区間になる。連続入力では応答が後続区間に入るため、入力1回の描画回数と同一視しない。

| 1920×1080 | 9×9 | 43 | 205 | 496 | 1225〜1279 | 181.875〜236.359 | 18 |
| 1920×1080 | 30×16 | 43 | 205 | 496 | 1238〜1279 | 181.875〜236.359 | 18 |
| 1280×800 | 9×9 | 43 | 205 | 496 | 1225〜1279 | 181.875〜236.359 | 18 |

| 960×1080 | 30×16 | 43 | 205 | 496 | 1799〜1832 | 181.875〜214.266 | 0 |

寸法はCSS px。全ケース15キーで、計測区間のscrollYは0のまま。960×30列では結果欄がviewport外にあり、layout-shiftは0でもページ高さが変わる。直前の入力があるlayout-shiftも収集しており、表はCLSスコアではない。

1920×9列の100ms間隔入力では、値入力1回につき盤面4回・凡例20回・同寸法設定48回。矢印移動は盤面2回・同寸法設定4回。drawはCanvasのclearRect呼び出しで数えており、GPUのpaint回数や画面全体の再描画回数を表す値ではない。

生JSON（各キー、描画、寸法設定、ResizeObserver、layout-shift、フォーカス、スクロール、rAFで変化したgeometry）、画面画像、動画は `test/artifacts/issue-24/` に出力した。圧縮JSON・前後の全6画像・9列と30列の前後動画・段階別集計を [保存証跡](evidence/issue-24/README.md) にコピーしてGit管理する。計測用コードはproduction bundleへ組み込まない。

## 要因別の比較と修正

| 段階 | 変更 | 盤面描画 | 凡例描画 | 同寸法設定 | ページ・結果欄の高さ変動 | layout-shift |
| --- | --- | ---: | ---: | ---: | --- | ---: |
| baseline | 修正前 | 43 | 205 | 496 | あり | 18（960px・30列は0） |
| result-space | 状態2行・説明3行・件数1行・有効policy1行の最小スペース | 25 | 115 | 280 | 0 | 0 |
| canvas-size | 上記に盤面Canvasの同寸法設定抑制を追加 | 25 | 115 | 230 | 0 | 0 |
| legend-cache | 上記に凡例の記号・DPRによるキャッシュを追加 | 25 | 0 | 0 | 0 | 0 |
| final | 上記に選択/focusinの重複描画抑制と幅だけのResizeObserverを追加 | 24 | 0 | 0 | 0 | 0 |

各段階は同じ15キー・全6ケース。描画・寸法設定の合計は全6ケースで一致した。100ms間隔の値入力は盤面4回から2回、矢印移動は2回から1回になった。最終段階の2変更はそれぞれ別の回帰テストでも分離して比較した。選択/focusinは矢印1回の描画が2→1、ResizeObserverは情報欄だけを500pxへ広げた際の盤面描画が1→0になった。

結果欄の高さ変動がworkspaceのResizeObserverを介して追加renderを起こすことは、スペース確保だけで盤面/凡例描画が減る比較で確認できた。Canvas寸法設定の抑制だけでは描画回数も高さも変わらない。主にレイアウト安定化がページの動きと追加描画を解消し、他の修正で不要な初期化・凡例/選択の再描画を取り除いた。

最終計測ではページ高さが1920pxと1280pxの両盤面で1364px、960px・9列で1356px、960px・30列で1938pxに固定された。結果欄は全ケース285.453125px、入力中scrollYは0。解析中は旧提案を消し、完了後に新しい観測に対応する提案を描き直す動作を保つ。固定上限やoverflowで文字を隠す方式ではなく最小スペースなので、長い文言や大きい文字は必要に応じて広がる。

## 再現

Mac上でproduction buildを作成し、計測する。

```sh
npm run build
INPUT_EVIDENCE_DIR=test/artifacts/issue-24/current npx tsx scripts/ui/measure-input.ts
```

baselineを再生成する場合は修正前の製品コードを使う。修正後は `INPUT_EVIDENCE_DIR=test/artifacts/issue-24/final` へ出力して比較する。JSONには対象commit・未コミット差分のファイル一覧・OS・ブラウザ・日時・URL・DPR・viewportを含む。legend-cache/finalの生JSONには計測時の製品コード差分も含む。前段の変更内容は上記の表に記録した。

任意の手動入力の追加調査には、DevToolsのSources → Snippetsで [`scripts/ui/input-probe.js`](../../scripts/ui/input-probe.js) を実行する。盤面を作成し解析終了後に `inputProbe.reset()`、セルへフォーカスして入力、`copy(JSON.stringify(inputProbe.report(), null, 2))` で記録をコピーする。`inputProbe.stop()` でプロトタイプとリスナーを復元する。再読み込み後は再実行が必要。これは今回の追加受け入れ条件ではない。

プローブはCanvasの寸法setterとclearRectをラップするため計測負荷がある。Performance録画とプローブを外した画面録画も比較する。データの送信・ブラウザストレージへの保存は行わない。

## 回帰テスト

`test/browser/input-stability.test.ts` は解析応答を80ms遅延させ、入力直後と解析完了後のgeometryを比較する。修正前に最初の7ケースが期待通り失敗した（6ケースの高さ変動、1ケースの同寸法Canvas設定）。後続の凡例・選択・情報欄だけの高さ変更も、それぞれ対応する修正前に失敗を確認した。遅延fixtureでも計算は実solverを使う。

新規テストでは、矛盾を起こす8の入力と復旧、観測と提案の一致、フォーカス維持、DPR 1→2、1280px→960pxの配置変更、正方形セル・横スクロールなし、有効policy文言の空⇄再検討の遷移も確認する。
