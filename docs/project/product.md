# 製品定義

## 目的

この製品は、デスクトップブラウザで動作するマインスイーパーsolverです。盤面と画像は完全にローカルで扱い、将来は画像支援を受け付けられるようにしますが、外部の分析APIやバックエンドには依存しません。

## 最初のMVP

最初のMVPは、画像認識なしでも、手動盤面入力とsolverでマインスイーパーの問題を解けるブラウザアプリです。利用者は幅、高さ、総地雷数を入力し、すべて閉じた状態の盤面から始めます。マウスとキーボードで閉じたセル、空きセル、旗、数字の1から8を入力でき、盤面を検証します。solverは確実に安全なセル、確実に地雷のセル、最善の推測候補を提案します。

画面は日本語UIとし、マウスだけでなくキーボードでも盤面を編集できるようにします。キーボード操作中のフォーカスを見える状態に保ち、色だけに頼らず記号、枠、マーカー形状でも入力と提案を区別します。入力、検証、solverの実行は完全にローカルで行います。

盤面の観測値とsolverの提案は独立した状態として保持し、solver結果で利用者の入力盤面を上書きしません。盤面を更新するたびにrevisionを進め、更新前に開始した非同期のsolver結果は破棄します。

## 通信・保存・診断報告

「ローカル処理」は、アプリが画像・盤面・診断データを外部へ送信せず、解析をブラウザ内で実行することを指します。ページ表示や解析に必要な静的ファイルの取得には通信が発生します。GitHub PagesではGitHubがアクセス時のIPアドレスをセキュリティ目的で記録します（[GitHub公式説明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages#data-collection)）。現在の手動MVPには画像入力はありません。

盤面と解析結果の履歴は、現在を含む直近100盤面をページ内のメモリに保持します。localStorage・sessionStorage・IndexedDBへの自動保存は行いません。古い履歴は上限で削除し、再読み込みやページ終了で盤面・履歴は消えます。

アプリから診断データを自動送信しません。利用者自身によるJSONダウンロードと、その後のGitHub Issueへの投稿は別の操作として扱います。報告は利用者自身が選び、公開Issueの本文・添付ファイルが公開されることを案内します。現在の仕様と診断機能の詳細は[通信・保存・診断報告の説明](privacy.md)を参照してください。

開発者向け診断は、ページ末尾の折りたたみメニューから明示的に有効化した後の解析のみ、直近100件までメモリ内に記録します。同じメニューからJSON出力・履歴削除を行えます。OFFで記録を停止して実行中の記録を除外し、完了済み履歴は削除するまで残します。再読み込みで履歴と設定は消えます。永続保存・自動送信は行いません。報告は利用者が任意でGitHub Issueに行い、所有者のローカル調査にも使えます。[診断の取得・再実行手順](solver-diagnostics.md)を参照してください。

## 安全契約

不確実なセルや、入力時の検証で判明する局所矛盾・総地雷数との矛盾がある場合は、solverによる提案解析を開始せず、利用者の確認または修正を待ちます。事前検証を通過した盤面でも、solverが制約全体を満たす配置がないと判定した場合は盤面矛盾として扱い、確定安全セル、確定地雷セル、推測候補を提案しません。認識の不確実性、盤面の矛盾、確定手がなく推測を要する正常な状態、探索上限への到達は、それぞれ別の状態として扱います。

利用者が手動で修正した場合は、認識を再実行せずに盤面のrevisionを更新し、検証とsolverだけを再実行します。これにより、手動入力だけで安全に問題を解け、将来の画像支援の結果も同じ修正経路で扱えます。

安全契約は次の順で適用します。

1. 盤面更新時にrevisionを進め、古い非同期結果を破棄する。
2. 不確実なセルと指定寸法との不一致があれば確認を待つ。それ以外は旗を確定地雷として局所制約と総地雷数・旗数・閉じたセル数を検証する。矛盾があれば提案解析を開始しない。
3. 検証済み盤面を、旗を固定地雷とした前提で解析する。
4. solverが全体矛盾を返した場合は提案を表示せず、数字・入力旗・総地雷数の確認を促す。自動再検討は行わない。
5. 成立する盤面に対してだけ、盤面観測とは別のレイヤーに確定安全セル、確定地雷セル、推測候補を表示する。

## 入力旗の扱い

入力旗は常に確定地雷として扱い、入力旗そのものへ安全・地雷・推測候補は提案しません。常時再検討と矛盾時の自動再検討、方式を選ぶUIは削除しました。誤った旗は手動で閉じたセルへ直すか、Undoで旗を置く前へ戻してください。

誤った入力旗でも数字と矛盾しなければ、その旗を前提とした提案が出ます。旗が正しいことは利用者が確認する必要があります。入力旗とsolverが提案する地雷は、表示上も別の状態として扱います。

## 盤面・解析結果のUndo/Redo

「元に戻す」「やり直す」のボタンで、幅・高さ・総地雷数と全セルのvalue/source/uncertain、保存済み解析結果を復元します。復元先がないボタンはdisabledです。TabとEnter/Spaceで操作でき、独自のUndoキーボードショートカットは追加しません。

セル観測の変更、リセット、盤面作成は各1操作として記録します。同じ寸法・総地雷数・全セル観測への操作は履歴を増やしません。source/uncertainが変わる手動確認は編集として記録します。選択・フォーカス・パレット・入力方式は履歴対象外です。Undo後の新編集はRedo側を破棄し、再解析だけでは履歴を増やしたりRedoを破棄したりしません。

保存済み成功結果（solved/guess-required）を優先して復元します。同じ盤面の再解析がlimit・矛盾・エラーになっても以前の成功結果を保持し、別entryへ移って戻ったときに表示します。成功結果がなければ保存済みの完了状態を復元します。解析中・失敗時の現在表示には以前の提案を重ねません。

保存結果の復元ではWorkerを起動しません。結果のない未完了entryへ戻る場合だけ検証して新解析し、不正な盤面なら確認状態を表示します。復元でもrevisionを進め、requestIdを巻き戻さず、古い応答を拒否します。盤面作成formは設定の変更時と、Undo/Redoで実際に履歴を移動したときに復元先へ同期し、入力エラーも解除します。同じ設定への復元でも同期します。通常の再描画・セル編集・解析応答と、移動先がないUndo/Redoでは未送信値を保ちます。

履歴一覧・永続保存・提案地雷の一括旗反映はありません。履歴は保持範囲の盤面へ戻って確認・修正する機能であり、探索量の削減や性能改善を保証しません。探索予算200,000ノード・Worker待機5秒は変更しません。編集履歴と開発者向け診断履歴は独立します。[Issue #26の変更・検証記録](issue-26-trusted-flags-history.md)を参照してください。

## MVPの非対象

最初のMVPには、画像アップロード、クリップボード、ドラッグ＆ドロップ、画面キャプチャ、セル認識、自動クリック、バックエンド、数値による確率表示を含めません。

## 後続マイルストーン

後続では、画像入力、採用済み認識器の統合、画像支援を追加します。スクリーンショットと利用者が手動確認した盤面をfixture候補として出力する機能は、別途の設計承認後に、利用者が明示的に操作した場合だけ提供します。

画像支援を追加した後も、盤面を検出できない場合や認識結果の確認が必要な場合は、直前の有効な盤面を保持し、手動入力と修正を利用可能な経路として残します。

## 認識との関係

認識は盤面入力を強化しますが、最初に役立つ製品の前提ではありません。認識研究の採用判断は認識統合をゲートしますが、手動盤面入力型MVPの進行を止めません。

## 対応環境

対象はデスクトップWindowsとし、最新Chromeを主要ブラウザ、Edgeを同等の動作を想定するブラウザとします。開発とCIはMacおよびLinuxでも再現可能にし、正式なブラウザ評価にはChromiumを使用します。

## レイアウト

盤面セルは常に正方形とし、Canvas内にはスクロールを設けません。盤面の横に情報欄を置いてもセルを24 CSS px以上に保てる場合は右サイドバーを使い、保てない場合は情報欄を盤面の下へ移します。必要な縦スクロールはページ全体に限定します。確認対象は1920×1080、1280×800、FHDのハーフ幅相当です。

## MVPの検証条件

- 盤面モデル、入力検証、基本規則、集合差分、独立成分、全体地雷数、固定地雷としての入力旗、全体矛盾、同率の推測候補を自動テストする。
- 小盤面では総当たりoracleとsolver結果を比較する。
- マウスとキーボードによる盤面作成、見えるフォーカス、盤面観測とsolver提案の表示区別、revisionと非同期結果の整合を検証する。
- Undo/Redoの上限、分岐、snapshot独立性、結果復元とWorker非起動、未完了entryの再解析、古い応答拒否を検証する。
- Chromium E2Eで、盤面情報の設定と手動入力から検証、solver提案、エラー表示までのMVPフローを確認する。
- 対象レイアウトで正方形セル、Canvas内スクロールの不在、情報欄の配置を確認する。
- 静的ファイル取得の通信とアプリによるデータ送信を区別し、画像・盤面・診断データを外部へ送らず、production buildでもバックエンドや外部解析APIを必要としないことを確認する。
- ページ内メモリでの保持とブラウザ保存領域への永続保存を区別し、UI・README・[通信・保存・診断報告の説明](privacy.md)が実装に一致することを確認する。
