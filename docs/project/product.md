# 製品定義

## 目的

この製品は、デスクトップブラウザで動作するマインスイーパーsolverです。盤面と画像は完全にローカルで扱い、将来は画像支援を受け付けられるようにしますが、外部の分析APIやバックエンドには依存しません。

## 最初のMVP

最初のMVPは、画像認識なしでも、手動盤面入力とsolverでマインスイーパーの問題を解けるブラウザアプリです。利用者は幅、高さ、総地雷数を入力し、すべて閉じた状態の盤面から始めます。マウスとキーボードで閉じたセル、空きセル、旗、数字の1から8を入力でき、盤面を検証します。solverは確実に安全なセル、確実に地雷のセル、最善の推測候補を提案します。

画面は日本語UIとし、マウスだけでなくキーボードでも盤面を編集できるようにします。キーボード操作中のフォーカスを見える状態に保ち、色だけに頼らず記号、枠、マーカー形状でも入力と提案を区別します。入力、検証、solverの実行は完全にローカルで行います。

盤面の観測値とsolverの提案は独立した状態として保持し、solver結果で利用者の入力盤面を上書きしません。盤面を更新するたびにrevisionを進め、更新前に開始した非同期のsolver結果は破棄します。

## 安全契約

不確実なセルや、入力時の検証で判明する局所矛盾・総地雷数との矛盾がある場合は、solverによる提案解析を開始せず、利用者の確認または修正を待ちます。事前検証を通過した盤面でも、solverが制約全体を満たす配置がないと判定した場合は盤面矛盾として扱い、確定安全セル、確定地雷セル、推測候補を提案しません。認識の不確実性、盤面の矛盾、確定手がなく推測を要する正常な状態、探索上限への到達は、それぞれ別の状態として扱います。

利用者が手動で修正した場合は、認識を再実行せずに盤面のrevisionを更新し、検証とsolverだけを再実行します。これにより、手動入力だけで安全に問題を解け、将来の画像支援の結果も同じ修正経路で扱えます。

安全契約は次の順で適用します。

1. 盤面更新時にrevisionを進め、古い非同期結果を破棄する。
2. 不確実なセルと指定寸法との不一致があれば確認を待つ。それ以外は選択中の旗policyで局所制約と総地雷数・旗数・閉じたセル数を検証する。旗の尊重による矛盾で自動再検討が有効な場合は、入力旗を未確定セルとして再検証し、それでも矛盾が残れば提案解析を開始しない。
3. 検証済み盤面を選択中の旗policyで解析する。
4. solverが全体矛盾を返した場合は提案を表示しない。入力旗を尊重する解析が矛盾し、自動再検討が有効な場合だけ、入力旗を未確定セルとして再解析する。
5. 成立する盤面に対してだけ、盤面観測とは別のレイヤーに確定安全セル、確定地雷セル、推測候補を表示する。

## 入力旗の扱い

既定では、利用者が入力した旗を確定地雷として尊重します。利用者は、入力旗を未確定セルとして扱う再検討policyを選択できます。また、自動再検討を有効にした場合、旗を尊重した解析が局所制約、全体制約、または総地雷数と両立しないときに限り、入力旗を未確定セルとして再解析します。

誤った入力旗を含んでいても成立する配置が存在する場合、その誤りを自動では検出できません。尊重policyではこの制約を利用者へ明示し、完全な再評価が必要な場合は再検討policyを使用します。入力旗とsolverが提案する地雷は、表示上も別の状態として扱います。

## MVPの非対象

最初のMVPには、画像アップロード、クリップボード、ドラッグ＆ドロップ、画面キャプチャ、セル認識、自動クリック、バックエンド、数値による確率表示を含めません。

## 後続マイルストーン

後続では、画像入力、採用済み認識器の統合、画像支援を追加します。スクリーンショットと利用者が手動確認した盤面をfixture候補として出力する機能は、別途の設計承認後に、利用者が明示的に操作した場合だけ提供します。

画像支援を追加した後も、盤面を検出できない場合や認識結果の確認が必要な場合は、直前の有効な盤面を保持し、手動入力と修正を利用可能な経路として残します。

## 認識との関係

認識は盤面入力を強化しますが、最初に役立つ製品の前提ではありません。認識研究の採用判断は認識統合をゲートしますが、手動盤面入力型MVPの進行を止めません。

## 対応環境

対象はデスクトップWindowsとし、最新Chromeを主要ブラウザ、Edgeを同等の動作を想定するブラウザとします。開発とCIはMacおよびLinuxでも再現可能にし、正式なブラウザ評価にはChromiumを使用します。

## レイアウト

盤面セルは常に正方形とし、Canvas内にはスクロールを設けません。盤面の横に情報欄を置いてもセルを24 CSS px以上に保てる場合は右サイドバーを使い、保てない場合は情報欄を盤面の下へ移します。必要な縦スクロールはページ全体に限定します。確認対象は1920×1080、1280×800、FHDのハーフ幅相当です。

## MVPの検証条件

- 盤面モデル、入力検証、基本規則、集合差分、独立成分、全体地雷数、入力旗policy、全体矛盾、同率の推測候補を自動テストする。
- 小盤面では総当たりoracleとsolver結果を比較する。
- マウスとキーボードによる盤面作成、見えるフォーカス、盤面観測とsolver提案の表示区別、revisionと非同期結果の整合を検証する。
- Chromium E2Eで、盤面情報の設定と手動入力から検証、solver提案、エラー表示までのMVPフローを確認する。
- 対象レイアウトで正方形セル、Canvas内スクロールの不在、情報欄の配置を確認する。
- 画像や盤面情報を外部へ送らず、production buildでもバックエンドや外部解析APIを必要としないことを確認する。
