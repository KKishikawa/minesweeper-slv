# 通信・保存・診断報告

Issue #33で公開説明を整理した文書です。リポジトリ内の作業版の通信、メモリ保持、診断JSONの出力と報告を説明します。Issue #12の画像入力はローカル実装・Chromium検証済みで、Windows Chrome手動確認、main統合、Pages配信は未完了です。公開済み手動MVPの証跡は変更しません。

画面では、ヘッダーの「端末内で解析 · 盤面の外部送信なし」ボタンから詳細を開けます。説明はモーダルダイアログに表示し、「閉じる」またはEscで閉じるとボタンへフォーカスを戻します。

## 現在の動作

| 操作・データ | 処理と保持 | 通信・公開 |
| --- | --- | --- |
| ページ表示・Worker起動 | HTML・CSS・JavaScript・Workerの静的ファイルを取得 | ファイル取得の通信が発生する |
| 手動入力した盤面・解析結果 | ブラウザ内で解析し、現在を含む直近100盤面と保存済み結果をページ内メモリに保持。再読み込み・ページ終了で消去 | アプリは盤面を外部へ送信しない |
| ブラウザの保存領域 | localStorage・sessionStorage・IndexedDBへの自動保存なし。Service Worker登録なし | アプリによるデータ送信の有無とは別の確認項目 |
| 取得画像 | ファイル・貼り付け・ドロップ・画面共有から取得し、最新1枚だけをページ内メモリに保持。表示専用で、画像履歴・画像エクスポートなし | アプリは画像を外部へ送信しない |
| 画面共有 | 明示操作で開始・現在フレーム取得・停止。ページ離脱・disposeでも停止 | アプリから共有画像を送信しない。ブラウザ・OSの共有元選択を使用 |
| 診断履歴・JSONダウンロード | 明示的な有効化後の解析を直近100件までページ内メモリに保持。JSON出力・履歴削除が可能 | アプリから診断データを自動送信する機能なし |
| 利用者自身による不具合報告 | 利用者が内容を確認して投稿するか選ぶ | GitHub Issueへの投稿はGitHubへの送信。公開Issueの本文・添付ファイルは公開される |

「端末内で解析」「盤面の外部送信なし」はアプリのデータ処理を説明する表現です。静的ファイル取得を含めたすべての通信が発生しないことや、ページ内メモリにもデータを保持しないことを意味しません。

GitHub Pagesでは、GitHubがアクセス時のIPアドレスをセキュリティ目的で記録します。これはアプリによる盤面・画像・診断データの送信とは別です。[GitHub公式説明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages#data-collection)を参照してください。

## 盤面・解析結果の編集履歴

Undo/Redoの履歴は、盤面寸法・総地雷数・全セルの観測と、完了した解析結果・最後の成功結果を現在を含む100盤面まで保持します。古い履歴は上限で削除し、Undo後の新しい編集はRedo側を破棄します。リセットも実際に盤面が変われば履歴へ追加するため、再読み込みまで以前の盤面が残ります。再解析は履歴を増やしません。

履歴一覧・JSON出力・永続保存はなく、再読み込みやページ終了で消えます。以下の診断履歴とは別の保持です。診断のOFF・削除は編集履歴を消しません。保存済み解析結果の復元ではWorkerを起動せず、診断entryも追加しません。未完了で結果のない盤面へ戻り、実際に新解析した場合は診断ONなら記録します。

## 画像の保持と共有停止

画像は表示のみです。盤面を自動入力する機能はまだありません。画像操作だけでは盤面・Undo/Redo履歴・solver実行・診断履歴を変更しません。HTMLや外部URLを画像として取得しません。

成功画像を置き換えると以前の画像への参照を外します。取込失敗やキャンセルでは最後の成功画像を保ちます。「画像をクリア」で画像・プレビューを消しますが、共有は継続します。「共有を停止」やブラウザ側の停止では最後の取得画像が残ります。パネルを閉じても外側の停止ボタンを使えます。

再読み込み・ページ離脱・disposeでは画像を消し、共有と未完了取込を終了します。画像・入力Blob・取得元情報をlocalStorage・sessionStorage・IndexedDBへ自動保存しません。Service Workerは登録しません。診断JSONにも画像の画素・ファイル名・共有元のラベルを含めません。

[Issue #12の検証記録](issue-12-image-input.md)には、production buildでの通信・保存・診断検証と、未実施のWindows Chrome手動確認を記載しています。共有元選択を置き換えた自動テストは、OSの選択画面を検証したものではありません。

## 診断履歴とJSONダウンロード

ページ末尾の「開発者向け診断」から「診断履歴を取得する」を有効にします。初期状態はOFFで、有効化前に開始した解析は記録しません。有効化後にWorkerへ依頼した解析を、実行中も含めて直近100件までページ内メモリに保持します。

OFFにすると取得を停止して実行中の記録を除外します。完了済み履歴はOFF後もダウンロード・削除できます。再読み込みやページ終了で履歴と設定は消え、ブラウザの保存領域には永続保存しません。

JSONには解析開始時の全セル観測、盤面寸法・総地雷数、固定方式を示すmetadata（policy/effectivePolicyはtrusted、autoReconsiderはfalse）、解析予算・待機上限、停止理由・経過時間・探索統計、build情報を含みます。内容と再実行方法は[診断の取得・再実行手順](solver-diagnostics.md)を参照してください。

履歴取得は端末内での保持、JSONダウンロードは利用者が端末へファイルを保存する操作、その後のIssue報告は利用者がGitHubへ投稿する操作です。アプリによる診断データの自動送信や外部受付サービスはありません。

## 不具合を報告する場合

報告するか、どの情報を添えるかは利用者自身が選べます。[GitHub Issue](https://github.com/KKishikawa/minesweeper-slv/issues)へ投稿する前に本文と添付ファイルの内容を確認してください。公開Issueでは投稿内容が公開されます。JSONのダウンロードだけではIssueへの投稿は行いません。

## 検証記録との関係

日付・対象commit付きの公開検証記録は、その時点の実装についての事実として残します。「storageなし」などの過去の結果は、将来の診断履歴保持の仕様を表すものではありません。現在の動作の確認では、静的ファイル取得、アプリからのデータ送信、メモリ保持、ブラウザ保存領域への保存、明示操作によるファイル出力を区別します。
