# ロードマップ

## 現在のマイルストーン

現在のマイルストーンは、画像認識に依存しない**手動盤面入力型MVP**です。手動で入力した盤面をローカルのsolverで解けることを、最初に利用者へ届けます。

## Track 1: 手動盤面入力型MVP

実行順序は `#9 -> #10 -> (#11 and #14 in parallel) -> #15 -> #16` です。

PR #20で#10・#11・#14・#15相当の実装とテストがmainへ統合済みです。#16は2026-10-10にWindows実機記録と合意済みChromium補完、GitHub Pages配信・公開後smokeまで完了しました。[公開・検証記録](manual-mvp-release.md)を参照してください。以下の依存表は着手条件を表し、GitHub Issueの状態は各Issueを参照します。

- #9: 手動盤面入力型MVPの[実装計画](../superpowers/plans/2026-09-13-manual-board-mvp.md)を作成する（計画作成済み）。
- #10: ブラウザ基盤、盤面モデル、validation、worker境界を確立する。
- #11: solverを実装する。
- #14: 盤面描画と手動入力を実装する。
- #15: #11と#14を統合し、MVPの操作フローと日本語UIを整える。
- #16: 手動盤面入力型MVPの品質とリリース準備を確認する。

Windows実機フィードバックから[#22〜#26](manual-mvp-windows-feedback-2026-10-10.md)を起票しました。#22の凡例と入力旗の視認性はPR #27で修正・Chromium確認済みです。#23はフォーカス復帰時の誤入力、#24はちらつき調査、#25は解析限界の診断、#26は旗policyの説明改善です。具体的な改善方式は仮説検証後に選びます。

## Track 2: 認識研究

実行順序は `#5 -> #6 -> #7 -> #8` です。

- #5: 認識方式と採用条件を設計する。[設計提案](../superpowers/specs/2026-10-11-next-cell-recognition-design.md)を作成済み、レビュー待ち。
- #6: 評価fixtureとブラウザ変換マトリクスを整備する。
- #7: 境界を定めたfeasibility spikeを実施する。
- #8: 評価結果にもとづき、認識器を採用するか判断する。

## Track 3: 画像支援と認識統合

- #12: ファイル、クリップボード、ドラッグ＆ドロップ、画面キャプチャを共通のpixel表現に変換する画像取得を実装する。
- #13: #8で採用された認識器を、#10の盤面モデルと#14の手動入力境界、#12の画像取得、レビュー状態、改訂処理へ統合する。

fixture候補のエクスポートは将来のマイルストーンであり、現在のIssueにはしません。別途の製品設計承認後、利用者の明示的な操作だけで実行できるものとします。

## マイルストーンごとの品質ゲート

品質確認は、認識に依存する最後の一段階ではなく、出荷可能なマイルストーンごとに行います。#16では手動盤面入力型MVPの品質を確認します。画像取得の品質は#12のマイルストーンで、認識統合の品質は#13のマイルストーンで確認します。公開リリースの品質は、対象となる製品範囲を別途定義したマイルストーンで確認します。
